## Cross-Phase Integration

### API Security Architecture

All admin endpoints (phases 8-11) are protected by dual-layer guards:
- Path-level: `AppEndpoints.SECURED_MAPPINGS` (11 entries via `Map.ofEntries()`) consumed by `@Order(2)` JWT chain
- Method-level: `@PreAuthorize("hasRole('ADMIN')")` on each controller class or method

Client analytics endpoints (phase 12) are protected by the `@Order(1)` API-key chain via `ClientSecurityConfiguration.securityMatcher` — consistent with `SmsResource` and all other client endpoints. `CLIENT_ANALYTICS` is intentionally absent from `SECURED_MAPPINGS`.

### Shared Services (Phase 12 + 8/9)

Phase 12 adds client-scoped methods to existing Phase 8/9 services:
- `DeliveryAnalyticsService.getClientDeliveryStats` / `getClientSegmentTotals` — same underlying `findDeliveryStats` query; non-null clientId always scopes to one client
- `SpendService.getClientNetCreditsConsumed` — same underlying `findSpendSummary` query; non-null clientId always scopes to one client

No behavioral conflict with admin methods (nullable clientId = global aggregate).

### Audit Event Pipeline (Phase 11)

All 8 hook points in v1.0 services are wired:
- `ClientService`, `TopupService`, `ApiKeyService` (admin + client paths), `SmsService`, `WebhookService`
- `AuditEventListener` swallows all exceptions — audit failures never break callers
- `AuditEventService.record()` uses `@Transactional(REQUIRES_NEW)` — audit commits independently of outer TX

## Tech Debt

### Non-blocking structural issues

**Phase 12:**
- `ClientCreditConsumptionResponse` is placed in `gateway.analytics.contract` but imported by `SpendService` in the `gateway.spend` package. Minor cross-module coupling. No runtime impact; could be relocated to `gateway.spend.contract` in a future refactor.

**Phase 11:**
- `WEBHOOK_DELETED` in `AuditEventType` is unwired — no delete endpoint in v8 API contract. Will need wiring when a delete endpoint is added.
- `SMS_SEND_SUBMITTED` fires before recipient row persistence (after `sendRequestRepo.save()`, before `recipientRepo.save()` loop). An audit record can exist for a send where recipient rows failed to persist. By-design per AUDT-03 scope, but a boundary condition to document.

**Phase 8:**
- `DeliveryDailyStat` does not include `total_segments` per day (the projection has the column but the service mapping drops it). Consistent with the plan spec; product owner should confirm if per-day segment breakdowns are needed.

### Carried from v1.0 (from STATE.md)
- Wrong error code for blank-message validation (`INVALID_SENDER_ID` used instead of a message-specific code)
- Duplicate `@RateLimited` on `SmsResource` AND `SmsService` fires AOP aspect twice per request
- TODO comments in `AppEndpoints.java` and `SecurityConfiguration.java`
- `APIKEY_PEPPER` env var must be set before production use; fallback is unsafe
