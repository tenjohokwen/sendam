### Bug Found and Fixed

**Pagination off-by-one** (found during audit, fixed in commit `8dd27e3`):

- `ServerPagination` emits 0-based page index via `page-change`
- `SmsMonitorPage.onPageChange`, `WebhooksPage.onEndpointsPageChange`/`onDeliveriesPageChange`, and `DlrDialog.onPageChange` were storing the 0-based value directly in a 1-based ref then subtracting 1 again in the API call
- Effect: navigating to page 2 of any paginated admin list always loaded page 1 data
- Fix: `page + 1` in each `onPageChange` handler to convert received 0-based value to 1-based storage
