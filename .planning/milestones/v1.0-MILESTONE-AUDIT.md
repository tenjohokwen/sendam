## Integration Gaps

### CRITICAL-1: `/v1/api/keys` Outside API Key Security Chain — CLOSED ✓

**Fix:** `AppEndpoints.CLIENT_API_KEYS = "/v1/api/**"` added; included in `ClientSecurityConfiguration.securityMatcher`. Confirmed by `clientApiKeysWithValidTokenReturns200` IT.

### CRITICAL-2: `TOPUPS_API` Dead Constant — CLOSED ✓

**Fix:** Removed from `AppEndpoints` and `ClientSecurityConfiguration`. Zero occurrences in `src/`.

### WIRING-1 (Medium): Sender ID Not Forwarded to Nexah — OPEN ⚠

**Root cause:** `NexahDispatchService.dispatch()` sends `nexahProperties.senderid()` (global account sender) to Nexah. The client-supplied `request.getSender()` is validated and stored in `SendRequest.sender` but never forwarded.

**Impact:** Clients who specify a custom sender ID see it accepted (ACCEPTED state, stored in DB) but Nexah delivers with the global account sender. The stored `SendRequest.sender` reflects what the client requested, not what was actually sent.

**Affected file:** `NexahDispatchService.java` — one-line fix: replace `nexahProperties.senderid()` with `request.getSender()` in the `NexahSendRequest` constructor call.

**Phase 7** (`07-fix-sender-id-forwarding`) plans this fix but has not been executed (0/1 plans complete).
