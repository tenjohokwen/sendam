# Milestone v1.1: Operations & Observability

**Status:** ✅ SHIPPED 2026-03-12
**Phases:** 8–12
**Total Plans:** 7

## Overview

Admin-facing operational visibility — what was sent, what was spent, what happened, and how the system is behaving. Plus client-facing self-service analytics.

All 17 requirements satisfied across 5 phases, 7 plans, ~15 tasks.

## Phases

**Goal**: Admin can query SMS delivery outcomes with filters and daily breakdown
**Depends on**: Nothing (read-only queries on existing sms tables)
**Requirements**: DANL-01, DANL-02, DANL-03
**Plans**: 1 plan

Plans:

- [x] 08-01: Delivery analytics data layer + admin REST endpoint

**Details:**
- `GET /api/admin/analytics/delivery-stats` — total_sent, delivered, failed, delivery_rate, total_segments, daily_breakdown (7 days max per call)
- `GET /api/admin/analytics/segment-totals` — total_segments with optional client/time filters

- New `gateway/analytics` module with contract/, repo/, service/, api/ layers
- Pattern established: `Repository<Object, Long>` for pure-aggregation queries (no entity binding)

### Phase 11: Audit Log

**Goal**: All significant platform events are recorded and queryable by admin
**Depends on**: Nothing (adds new table; hooks into existing service calls)
**Requirements**: AUDT-01, AUDT-02, AUDT-03, AUDT-04, AUDT-05
**Plans**: 3 plans

Plans:

- [x] 11-01: Audit data layer — V10 migration, entity, repository, contract types
- [x] 11-02: Write pipeline — AuditEventService (REQUIRES_NEW), AuditEventListener (exception-swallowing), hooks in 5 services
- [x] 11-03: Admin audit query endpoint — AdminAuditResource GET /events paginated

**Details:**
- `audit_event` table: id (TSID), event_type, client_id (nullable FK), actor, detail, occurred_at
- 11-constant AuditEventType enum covering all AUDT-01 through AUDT-04 trigger points
- AuditEventEntity extends BaseEntity (NOT AbstractAuditingEntity — append-only, no status column)
- AuditEventService.record() uses @Transactional(REQUIRES_NEW) — audit commits independently of outer TX
- AuditEventListener uses @EventListener (synchronous) + try/catch swallowing — audit failure never breaks callers
- Event hooks wired in: ClientService, TopupService, ApiKeyService (admin + client paths), SmsService, WebhookService
- WEBHOOK_DELETED defined in enum but intentionally unwired — no delete endpoint in v8 contract
- `GET /api/admin/audit/events` with optional clientId, from, to, @PageableDefault(size=20, DESC)
- ADMIN_AUDIT is the 11th Map.ofEntries() entry — Map.of() capped at 10

### Phase 12: Client Analytics

**Goal**: Clients can query their own delivery stats and credit consumption
**Depends on**: Phase 8 (shares query patterns with admin delivery analytics)
**Requirements**: CANL-01, CANL-02, CANL-03
**Plans**: 1 plan

Plans:

- [x] 12-01: Client analytics endpoints (delivery stats, segment totals, credit consumption)

**Details:**
- `GET /v1/analytics/delivery-stats` — total_sent, delivered, failed, delivery_rate, total_segments (no daily_breakdown)
- `GET /v1/analytics/segment-totals` — total_segments, from, to echoed (no client_id)
- `GET /v1/analytics/credits-consumed` — net_credits_consumed, from, to echoed (no per-type breakdown)
- clientId extracted exclusively from SecurityContextHolder — no @RequestParam; client A cannot see client B's data
- Secured by @Order(1) API-key chain (ClientSecurityConfiguration.securityMatcher claims /v1/analytics/**)
- CLIENT_ANALYTICS NOT in SECURED_MAPPINGS — JWT chain's /v1/** catch-all would double-claim it
- Reuses DeliveryAnalyticsService + SpendService with non-null clientId (always scoped)

## Milestone Summary

**Key Decisions:**

- `Repository<Object, Long>` (not JpaRepository) for pure-aggregation analytics repos — established in phase 8, confirmed in phase 9
- `Map.ofEntries()` mandatory for SECURED_MAPPINGS from phase 10 onward — Map.of() capped at 10 pairs
- `AuditEventEntity` extends BaseEntity only — append-only table must not inherit status column from AbstractAuditingEntity
- `AuditEventType` passed as parameter by callers — single ApiKeyService serves both admin and client paths
- `CLIENT_ANALYTICS` excluded from SECURED_MAPPINGS — client endpoints use @Order(1) API-key chain, not JWT chain
- `failureRatePct` passes -1.0f through — Resilience4j returns -1.0 for insufficient window data; not converted to 0.0
- `TOPUP_PENDING` excluded from credit spend aggregate — always amount=0, adds no information
- SMS audit detail contains recipientCount only — minimizes PII per AUDT-03
- `getClientSegmentTotals` reuses `findDeliveryStats` — same row has total_segments; no duplicate query needed
- `WEBHOOK_DELETED` left unwired — no delete endpoint in v8 contract; enum exists for future wiring

**Issues Resolved:**

- AppEndpoints.SECURED_MAPPINGS Map.of() cap (10 pairs) hit at phase 10 — resolved by migrating to Map.ofEntries()
- ApiKeyService signature change (added AuditEventType param) broke 5 test files — auto-fixed in plan 11-02

**Issues Deferred:**

- Missing .mvn/wrapper/maven-wrapper.properties — fallback to system mvn used; pre-existing environment issue
- Per-day segment totals not in daily_breakdown (only overall total_segments) — product owner should confirm if needed
- Boot smoke test (401 without key, 200 with valid key) on analytics endpoints — requires running instance

**Technical Debt Incurred:**

- `ClientCreditConsumptionResponse` placed in gateway.analytics.contract but imported by SpendService — minor cross-module coupling
- `WEBHOOK_DELETED` wired to nothing — correct now (no delete endpoint), but needs wiring when delete is added
- Carried from v1.0: wrong error code for blank-message validation, duplicate @RateLimited, TODO comments
