Create DeviationAlertManagementService.java in gateway/billing/service/.
Annotations: @Service, @Transactional, @Slf4j, @RequiredArgsConstructor.

Inject: SegmentDeviationAlertRepository segmentRepo, BalanceDeviationAlertRepository balanceRepo,
DeviationAlertEventRepository eventRepo, SecurityUtil securityUtil.

Implement four public methods:

--- listAlerts ---
Signature: public Page<DeviationAlertDto> listAlerts(DeviationAlertType type, AlertStatus alertStatus, Pageable pageable)

Routing logic:
- type == BALANCE → query balanceRepo.findByOptionalFilters(alertStatus, pageable); map results to DTOs with auditTrail=null
- type == SEGMENT or type == PLATFORM_FREEZE → query segmentRepo.findByOptionalFilters(type, alertStatus, pageable); map to DTOs with auditTrail=null
- type == null → query BOTH repos. Query segment with (null, alertStatus, Pageable.unpaged()); query balance with (alertStatus, Pageable.unpaged()). Merge the two result lists in Java, sort by createdDate DESC, then manually slice to match the requested Pageable (use PageImpl with the subList and total count). Map all to DTOs with auditTrail=null.

For the null-type case, the manual page slice formula:
  int start = (int) pageable.getOffset();
  int end = Math.min(start + pageable.getPageSize(), merged.size());
  List<DeviationAlertDto> pageContent = (start >= merged.size()) ? List.of() : merged.subList(start, end);
  return new PageImpl<>(pageContent, pageable, merged.size());

--- getAlert ---
Signature: public DeviationAlertDto getAlert(DeviationAlertType type, Long id)

Routing:
- type == BALANCE → balanceRepo.findById(id).orElseThrow(ResourceNotFoundException with "Balance deviation alert not found: " + id)
- type == SEGMENT or PLATFORM_FREEZE → segmentRepo.findById(id).orElseThrow(ResourceNotFoundException with "Segment deviation alert not found: " + id)

Fetch audit trail: eventRepo.findBySegmentAlertIdFkOrderByActedAtAsc(id) for segment types,
eventRepo.findByBalanceAlertIdFkOrderByActedAtAsc(id) for balance. Map to DeviationAlertEventDto list.

Return toDto(entity, auditTrail). The DTO auditTrail field is populated (not null).

--- acknowledge ---
Signature: public DeviationAlertDto acknowledge(DeviationAlertType type, Long id, String note)

1. Load entity (same routing as getAlert, with findById + orElseThrow).
2. Check: if (!entity.getAlertStatus().canTransitionTo(AlertStatus.ACKNOWLEDGED)) throw AlertStatusTransitionException("Cannot acknowledge alert " + id + " in status " + entity.getAlertStatus(), id, entity.getAlertStatus())
3. Save event: build DeviationAlertEvent with alertType=type, previousStatus=entity.getAlertStatus(), newStatus=ACKNOWLEDGED, adminNote=note, actedBy=securityUtil.getCurrentUserName(), actedAt=Instant.now(). Set segmentAlertIdFk or balanceAlertIdFk based on type. Save via eventRepo.save().
4. Update entity: entity.setAlertStatus(AlertStatus.ACKNOWLEDGED). Save via segmentRepo.save(entity) or balanceRepo.save(entity).
5. Fetch fresh audit trail and return toDto(entity, trail).

--- resolve ---
Signature: public DeviationAlertDto resolve(DeviationAlertType type, Long id, String note)

Same structure as acknowledge() but target status is RESOLVED. Check canTransitionTo(RESOLVED).
EventType = RESOLVED. Everything else identical.

--- toDto helpers ---
Implement two private mapping methods:
- private DeviationAlertDto toDto(SegmentDeviationAlert a, List<DeviationAlertEventDto> trail)
  Maps all fields; perRecipientBreakdown maps from RecipientDeviationEntry to RecipientBreakdownDto.
  nexahBalance=null, sendamBalance=null.
- private DeviationAlertDto toDto(BalanceDeviationAlert a, List<DeviationAlertEventDto> trail)
  Maps all fields. sendRequestRef=null, clientId=null, shortfallAmount=null, unrecoveredAmount=null,
  financialAction=null, clientFrozen=null, platformFrozen=null, perRecipientBreakdown=null.
- private DeviationAlertEventDto toEventDto(DeviationAlertEvent e)
  Maps all fields.

The toDto(SegmentDeviationAlert, null) path (list endpoint) sets auditTrail=null explicitly.

Note: Instant.now() for actedAt — no Clock injection; consistent with Phase 22/23 patterns.
Note: Do NOT publish DomainAuditEvent in this service for acknowledge/resolve — the audit trail is
stored in deviation_alert_event. AuditEventType additions are in Plan 04.
