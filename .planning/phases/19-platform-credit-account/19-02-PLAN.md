Create PlatformCreditService.java in package com.softropic.sendam.gateway.billing.service.

Class-level annotations: @Service, @Transactional, @Slf4j, @RequiredArgsConstructor

Dependencies (constructor injection):
- PlatformCreditBalanceRepository balanceRepository
- PlatformCreditLedgerRepository ledgerRepository

Method 1 — applyLedgerEntry (INTERNAL write method, called by TopupService and future phases):
Signature: public void applyLedgerEntry(PlatformLedgerEntryType type, long amount, String reference)
- Acquire pessimistic lock: PlatformCreditBalance lockRow = balanceRepository.findForUpdate().orElseThrow(() -> new ResourceNotFoundException("Platform balance not initialized", "platform_credit_balance"));
- Compute: long newBalance = lockRow.getBalance() + amount;
- Reject if negative: if (newBalance < 0) { throw new InsufficientPlatformBalanceException("Platform balance insufficient for operation", lockRow.getBalance(), Math.abs(amount)); }
- Write ledger entry: PlatformCreditLedgerEntry entry = PlatformCreditLedgerEntry.builder().entryType(type).amount(amount).balanceAfter(newBalance).reference(reference).status(EntityStatus.ACTIVE).build(); ledgerRepository.save(entry);
- Update balance row: lockRow.setBalance(newBalance); balanceRepository.save(lockRow);
- Log: log.info("Platform ledger entry written: type={}, amount={}, newBalance={}", type, amount, newBalance);
- Lock order comment: "// Lock order: (1) topup row [caller], (2) client credit balance [CreditService], (3) platform balance [here] — never invert this order"

Method 2 — recordNexahPurchase (Admin API method):
Signature: public RecordNexahPurchaseResponse recordNexahPurchase(RecordNexahPurchaseRequest request)
- Validate: amount > 0 is already enforced by @Positive on the request record; no extra check needed
- Generate reference: String reference = request.reference() != null ? request.reference() : "nexah_purchase"; (simple fallback — reference is optional)
- Call: applyLedgerEntry(PlatformLedgerEntryType.NEXAH_PURCHASE, request.amount(), reference);
- Read updated balance for response: PlatformCreditBalance updated = balanceRepository.findBalance().orElseThrow();
- Return: new RecordNexahPurchaseResponse(updated.getBalance(), request.amount(), Instant.now());
- Log: log.info("Nexah purchase recorded: amount={}, newBalance={}", request.amount(), updated.getBalance());

Method 3 — getBalance (Admin API method):
Annotation: @Transactional(readOnly = true)
Signature: public PlatformBalanceResponse getBalance()
- PlatformCreditBalance row = balanceRepository.findBalance().orElseThrow(() -> new ResourceNotFoundException("Platform balance not initialized", "platform_credit_balance"));
- Return: new PlatformBalanceResponse(row.getBalance(), row.getLastModifiedDate());

Method 4 — getLedgerHistory (Admin API method):
Annotation: @Transactional(readOnly = true)
Signature: public PlatformLedgerHistoryResponse getLedgerHistory(PlatformLedgerEntryType type, int page, int size)
- int effectiveSize = Math.min(size, 200);
- Pageable pageable = PageRequest.of(page, effectiveSize);
- Page<PlatformCreditLedgerEntry> pageResult = ledgerRepository.findByOptionalType(type, pageable);
- Map to DTOs: List<PlatformLedgerEntryDto> dtos = pageResult.getContent().stream().map(e -> new PlatformLedgerEntryDto(e.getCreatedDate(), e.getEntryType(), e.getAmount(), e.getBalanceAfter(), e.getReference())).toList();
- Return: new PlatformLedgerHistoryResponse(dtos, pageResult.getNumber(), pageResult.getSize(), pageResult.getTotalElements());

Imports needed: all billing contract classes, billing repo classes, common persistence, Spring Data Page/PageRequest/Pageable, Spring @Service/@Transactional, Lombok @Slf4j/@RequiredArgsConstructor, ResourceNotFoundException, EntityStatus, Instant.

CRITICAL: applyLedgerEntry is NOT @Transactional(readOnly) — it is a write method inside a @Transactional class-level annotation and must participate in the caller's transaction when called from TopupService.approve(). Do not add a new @Transactional on this method — the class-level @Transactional already covers it and Spring will propagate the caller's transaction.
