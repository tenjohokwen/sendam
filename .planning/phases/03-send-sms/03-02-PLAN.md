  <name>Task 1: SmsService — full sendSms orchestration and getStatus query</name>
  <files>
    src/main/java/com/softropic/sendam/client/service/SmsService.java
  </files>
  <action>
    Create SmsService as a @Service @Transactional @RequiredArgsConstructor @Slf4j bean.

    Dependencies to inject:
    - SendRequestRepository sendRequestRepo
    - SendRequestRecipientRepository recipientRepo
    - CreditReservationService creditReservationService
    - CreditService creditService  (for balance read after reservation)
    - RateLimitingService rateLimitingService
    - CamMobileValidator camMobileValidator

    Method: sendSms(Long clientId, SendSmsRequest request) → SendSmsResponse

    Implementation order (ALL steps must happen in this exact sequence — anti-pattern: validate after reserve):

    1. Idempotency check:
       Optional&lt;SendRequest&gt; existing = sendRequestRepo.findByClientIdAndSendRequestId(clientId, request.sendRequestId())
       If present → return toResponse(existing.get(), creditService.getBalance(clientId))
       Return immediately. Do NOT fall through to re-validation or re-reservation.

    2. Rate limit — N-token check for recipients/min (AUTH-05):
       int recipientCount = request.recipients().size()
       boolean allowed = rateLimitingService.tryConsume(String.valueOf(clientId), "sms_recipients", 1000L, 1L, TimeUnit.MINUTES, recipientCount)
       If !allowed → throw RateLimitExceededException("Recipient rate limit exceeded per minute")
       The @RateLimited annotation on sendSms also enforces 10 req/s (Phase 1 aspect). Add @RateLimited to the sendSms method with limitKey="sms_send" so the AOP aspect handles the per-second limit.

    3. Validate sender ID:
       private static final Pattern SENDER_ID_PATTERN = Pattern.compile("^[A-Z0-9]{1,11}$")
       If !SENDER_ID_PATTERN.matcher(request.sender()).matches() → throw ApiException using SmsError.INVALID_SENDER_ID
       Check how other services throw validation errors — look at CreditService for the ApiException/ErrorCode pattern.

    4. Validate message:
       If request.message() is blank → throw ApiException using a suitable error or IllegalArgumentException (Spring validation should catch @NotBlank on the DTO, but defend here as well)

    5. Validate all recipients — COLLECT ALL failures (do not fail on first):
       List&lt;String&gt; invalid = request.recipients().stream()
           .filter(r -> !isValidRecipient(r))
           .toList()
       private boolean isValidRecipient(String phone): call camMobileValidator.validate(phone) inside a try-catch; if it throws InvalidMobileNumberException → return false, else return true
       If invalid is not empty → throw ApiException using SmsError.INVALID_PHONE_NUMBER with message including invalid.toString()

    6. Validate scheduleTime (only if not null):
       If request.scheduleTime() is not null AND !request.scheduleTime().isAfter(Instant.now()) → throw ApiException using SmsError.INVALID_SCHEDULE_TIME

    7. Calculate segments:
       int segmentCount = SmsSegmentCalculator.calculate(request.message())
       long totalCredits = (long) segmentCount * recipientCount

    8. Reserve credits (throws InsufficientBalanceException if insufficient — already handled by existing ApiAdvice handler for ClientError.INSUFFICIENT_CLIENT_BALANCE):
       String reference = "sms:" + request.sendRequestId()
       long reservationId = creditReservationService.reserve(clientId, totalCredits, reference)

    9. Persist SendRequest row:
       SendRequest sendRequest = SendRequest.builder()
           .clientId(clientId)
           .sendRequestId(request.sendRequestId())
           .sender(request.sender())
           .message(request.message())
           .sendStatus(SendRequestStatus.ACCEPTED)
           .scheduleTime(request.scheduleTime())
           .messageCount(recipientCount)
           .segmentCount(segmentCount)
           .reservedCredits(totalCredits)
           .reservationId(reservationId)
           .status(EntityStatus.ACTIVE)
           .build()
       sendRequestRepo.save(sendRequest)

    10. Persist SendRequestRecipient rows (one per recipient):
        request.recipients().forEach(phone ->
            recipientRepo.save(SendRequestRecipient.builder()
                .sendRequestIdFk(sendRequest.getId())
                .clientId(clientId)
                .recipient(phone)
                .sendStatus(SendRequestStatus.ACCEPTED)
                .status(EntityStatus.ACTIVE)
                .build())
        )

    11. Read balance AFTER reservation (for response field):
        long balanceAfter = creditService.getBalance(clientId)

    12. Return toResponse(sendRequest, balanceAfter)

    Private helper toResponse(SendRequest req, long balanceAfter):
        return new SendSmsResponse(
            "req_" + req.getId(),
            req.getSendRequestId(),
            req.getMessageCount(),
            req.getSegmentCount(),
            req.getReservedCredits(),
            balanceAfter,
            req.getSendStatus().name()
        )

    Method: getStatus(Long clientId, String sendRequestId, int page, int pageSize) → MessageStatusResponse

    - Load SendRequest: sendRequestRepo.findByClientIdAndSendRequestId(clientId, sendRequestId)
      .orElseThrow(() → ResourceNotFoundException("Send request not found", "send_request"))
    - Clamp pageSize: Math.min(pageSize, 200) — follow CreditService pattern (max 200)
    - Load recipients: recipientRepo.findBySendRequestIdFkAndClientId(req.getId(), clientId)
    - Manual pagination: subList from page*pageSize to min((page+1)*pageSize, list.size())
    - Map each to MessageStatusEntry(recipient, sendStatus.name(), gatewayMessageId, providerMessageId, segmentsConsumed)
    - Return MessageStatusResponse(sendRequestId, req.getSendStatus().name(), page, pageSize, list.size(), pagedEntries)
