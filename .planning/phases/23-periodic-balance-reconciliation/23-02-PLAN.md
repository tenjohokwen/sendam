  <action>
    Read SegmentDeviationService.java first to understand the service pattern (class-level @Transactional, ApplicationEventPublisher, DomainAuditEvent construction with null clientId for platform events).

    1. Create BalanceDeviationAlertService.java in billing.service — mirrors SegmentDeviationService but for balance alerts. Owns the @Transactional write:
    - Class-level @Transactional, @Service, @Slf4j, @RequiredArgsConstructor
    - Injects: BalanceDeviationAlertRepository, ApplicationEventPublisher
    - Single public method createAlert(long nexahBalance, long sendamBalance, long delta):
      - Build BalanceDeviationAlert with nexahBalance, sendamBalance, delta, alertType=BALANCE, status=EntityStatus.ACTIVE
      - alertRepository.save(alert)
      - Publish DomainAuditEvent(AuditEventType.BALANCE_DEVIATION, null, "system", detail string)
        Note: clientId is null because DomainAuditEvent.clientId is documented as "nullable — null for events with no client target"
      - log.warn() with nexahBalance, sendamBalance, delta values

    2. Create BalanceReconciliationJob.java in billing.service — the @Scheduled job:
    - @Service, @Slf4j, @RequiredArgsConstructor (do NOT add @Transactional at class level — the HTTP call must be outside any transaction)
    - Injects: NexahClient, PlatformCreditService, BalanceDeviationAlertService
    - @Scheduled annotation using SpEL for minutes-to-ms conversion:
      @Scheduled(fixedDelayString = "#{${sendam.reconciliation.interval-minutes:15} * 60000L}")
    - reconcile() method structure (all non-transactional at this level):
      a. Fetch Nexah balance: nexahClient.fetchCreditBalance() — if throws any Exception, log.warn and return (skip this cycle, do NOT propagate)
      b. Fetch Sendam balance: platformCreditService.getBalance().balance() — read-only, brief transaction inside getBalance()
      c. Compute delta = nexahBalance - sendamBalance
      d. If delta == 0: log.debug("Balance reconciliation OK: nexah={}, sendam={}", ...) and return
      e. If delta != 0: alertService.createAlert(nexahBalance, sendamBalance, delta) — this opens a new transaction inside the service

    The separation of BalanceReconciliationJob (HTTP + comparison) and BalanceDeviationAlertService (@Transactional write) ensures the DB connection is NOT held during the Nexah HTTP call. This mirrors the SegmentDeviationService split pattern from Phase 22.
  </action>

  <done>BalanceDeviationAlertService.createAlert() compiles. BalanceReconciliationJob.reconcile() compiles with @Scheduled SpEL annotation. No DB connection held during Nexah HTTP call. All existing tests pass.</done>
