<objective>
Close three independent tech debt items from the v1.3 milestone audit: a credit reservation leak in
the stale-SMS recovery path, a latent NPE hazard from a boxed Long in an event record, and a
Javadoc typo on an exception class.

Purpose: Stale SMS requests (stuck in SUBMITTED for 24+ hours) currently have their credit
reservations permanently held because forceFinalize() never triggers billing finalization. Fix 1
closes this by publishing SmsFinalisedEvent with actualSegments=0, which routes through the existing
FinalBookingService zero-segments guard to release the reservation. Fix 2 changes
SmsFinalisedEvent.actualSegments from Long to primitive long, eliminating a theoretical NPE at the
event listener boundary. Fix 3 corrects a comment that says HTTP 400 when the actual runtime
response is HTTP 422.

Output: Four files changed. All existing 213 tests pass. One new test assertion added.
</objective>
