**routes.js** — Add an admin route group inside the `'/'` MainLayout children array, after the existing `profile` route and before the closing bracket. Do not modify any existing routes:

```javascript
{
  path: 'admin',
  meta: { requiresAuth: true, requiresAdmin: true },
  children: [
    { path: '', redirect: '/admin/clients' },
    { path: 'clients', component: () => import('pages/admin/ClientsPage.vue') },
    { path: 'topups', component: () => import('pages/admin/TopupsPage.vue') },
    { path: 'sms', component: () => import('pages/admin/SmsMonitorPage.vue') },
    { path: 'webhooks', component: () => import('pages/admin/WebhooksPage.vue') },
    { path: 'audit', component: () => import('pages/admin/AuditPage.vue') },
    { path: 'dashboard', component: () => import('pages/admin/AdminDashboardPage.vue') },
  ]
}
```

All page imports use lazy `() => import(...)` syntax. The `requiresAdmin: true` meta is set on the parent route — all children inherit it via `to.matched.some(...)`.

**router/index.js** — In the existing `Router.beforeEach` guard, add a `requiresAdmin` check AFTER the existing `requiresAuth` check and BEFORE the `requiresGuest` check:

```javascript
const requiresAdmin = to.matched.some((r) => r.meta.requiresAdmin)

// After the requiresAuth block:
if (requiresAdmin && !isAuthenticated) {
  next({ path: '/login', query: { redirect: to.fullPath } })
  return
}
// Note: full role verification is deferred to Phase 14 when the user store is built.
// The backend enforces ROLE_ADMIN at the API layer — a 403 is the security boundary.
// This guard prevents the blank-page experience for unauthenticated users only.
```

Do NOT add a role check against a Pinia store — no role store exists yet. Add a comment explaining this is intentional and that Phase 14 will wire the role check.

  </verify>
