<objective>
Create the Long-to-String safety utility, extend both i18n files with admin and pagination translation namespaces, establish the centralized api/ folder skeleton (FOUND-06), and create the useErrorHandler composable (FOUND-07).

Purpose: Backend Long IDs (PostgreSQL BIGSERIAL) can exceed JS Number.MAX_SAFE_INTEGER. Any admin page that displays an ID without conversion will silently corrupt values. This utility must exist before any admin page is built. The admin and pagination i18n keys must exist before ServerPagination.vue can reference them. The api/ folder and useErrorHandler composable must exist before Phase 14 admin pages make real API calls.

Output: `src/frontend/src/utils/longToString.js`, updated `en-US/index.js`, updated `fr-FR/index.js`, `src/frontend/src/api/admin/index.js`, `src/frontend/src/composables/useErrorHandler.js`.
</objective>

1. `longToString(value)` — converts a single Long value to String. Returns null if value is null or undefined. Returns String(value) otherwise. Add a JSDoc comment explaining why: "Java Long values can exceed JS Number.MAX_SAFE_INTEGER (2^53 - 1). Always call this on ID fields before displaying."

2. `normalizeLongIds(obj, fields)` — takes an object and an array of field name strings. Returns a shallow copy of the object with each named field converted using String(). Do NOT use BigInt. The strategy is display-only string coercion — no arithmetic is needed on IDs.
  </action>

- `longToString(null)` returns null
- `longToString("abc123")` returns `"abc123"`
- `normalizeLongIds({ id: 123, name: "test" }, ["id"])` returns `{ id: "123", name: "test" }`
