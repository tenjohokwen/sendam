**HealthRepository.java** — extends Repository&lt;Object, Long&gt; (NOT JpaRepository — no entity
binding needed; established project pattern from phases 8 and 9):
```java
@org.springframework.stereotype.Repository
public interface HealthRepository extends Repository<Object, Long> {

    @Query(value = """
        SELECT
            COUNT(*)                                                          AS total_attempts,
            COUNT(CASE WHEN d.attempt_status = 'FAILED'    THEN 1 END)       AS failure_count,
            COUNT(CASE WHEN d.attempt_status = 'EXHAUSTED' THEN 1 END)       AS exhausted_count
        FROM main.webhook_delivery d
        """, nativeQuery = true)
    WebhookStatsRow findWebhookStats();

    @Query(value = """
        SELECT
            COUNT(CASE WHEN r.send_status NOT IN ('ACCEPTED', 'CANCELLED') THEN 1 END) AS total_submitted,
            COUNT(CASE WHEN r.send_status IN ('COMPLETED', 'FAILED')        THEN 1 END) AS dr_received,
            COUNT(CASE WHEN r.send_status = 'FAILED'                        THEN 1 END) AS failed_count
        FROM main.send_request_recipient r
        """, nativeQuery = true)
    ProviderStatsRow findProviderStats();
}
```

CRITICAL — webhook SQL: use column `attempt_status` (NOT `status`). The `status` column on
WebhookDelivery is the inherited AbstractAuditingEntity lifecycle column (always ACTIVE) and is
unrelated to delivery outcome. The delivery outcome column is `attempt_status`.

CRITICAL — provider SQL: do NOT include 'FAIL_FINALIZED' in any recipient-level query.
FAIL_FINALIZED is only set on the parent send_request (by DrCallbackService.finalizeParentIfAllTerminal()).
Individual recipients reach terminal state at 'FAILED' (bad DR) or 'COMPLETED' (good DR). Including
FAIL_FINALIZED in a send_request_recipient query returns 0 rows for that status.

**CircuitBreakerHealthResponse.java** — Java record in gateway/health/contract/:
```java
public record CircuitBreakerHealthResponse(
    @JsonProperty("state")               String state,
    @JsonProperty("failure_rate_pct")    float  failureRatePct,
    @JsonProperty("failed_calls")        int    failedCalls,
    @JsonProperty("successful_calls")    int    successfulCalls,
    @JsonProperty("not_permitted_calls") long   notPermittedCalls
) {}
```
The `state` field holds the string name of the CircuitBreaker.State enum
(e.g. "CLOSED", "OPEN", "HALF_OPEN"). Pass -1.0f through for failureRatePct when the sliding
window is not yet full — do NOT convert to 0.0 (the -1.0 value is meaningful to the caller
as "insufficient data").

**HealthService.java** — in gateway/health/service/:
- Annotate: @Service, @RequiredArgsConstructor, @Transactional(readOnly = true), @Slf4j
- Inject: HealthRepository healthRepository, CircuitBreakerRegistry circuitBreakerRegistry
- Method getCircuitBreakerHealth():
  - CircuitBreaker cb = circuitBreakerRegistry.circuitBreaker("nexah");  // name MUST be "nexah" — matches @CircuitBreaker(name="nexah") in NexahClient and application.yaml
  - CircuitBreaker.Metrics m = cb.getMetrics();
  - Return new CircuitBreakerHealthResponse(cb.getState().name(), m.getFailureRate(), m.getNumberOfFailedCalls(), m.getNumberOfSuccessfulCalls(), m.getNumberOfNotPermittedCalls())
- Method getWebhookHealth():
  - WebhookStatsRow row = healthRepository.findWebhookStats();
  - Return new WebhookHealthResponse(row.getTotalAttempts(), row.getFailureCount(), row.getExhaustedCount())
- Method getProviderStats():
  - ProviderStatsRow row = healthRepository.findProviderStats();
  - double failureRate = row.getDrReceived() == 0 ? 0.0 : (double) row.getFailedCount() / row.getDrReceived() * 100.0;
  - Return new ProviderStatsResponse(row.getTotalSubmitted(), row.getDrReceived(), row.getFailedCount(), failureRate)

Do NOT inject CircuitBreakerRegistry into the controller — inject it into the service only.
