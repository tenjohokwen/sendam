<objective>
Wire the state machine: replace the Phase 3 stub dispatcher with real Nexah HTTP calls, process delivery reports to advance per-recipient states, finalize the parent send_request when all recipients reach terminal state, and settle billing via the existing CreditReservationService.debit().

Purpose: This is the core of Phase 4. NexahDispatchService submits messages; DrCallbackService processes DRs and closes the billing loop. The Flyway V6 migration adds finalized_at for the 30-day purge (Plan 03 depends on it).

Output: Messages flow ACCEPTED -> SUBMITTED (via scheduler + Nexah call), SUBMITTED -> COMPLETED/FAILED (via DR callback), parent transitions to FINALIZED/FAIL_FINALIZED with debit() settling the reservation.
</objective>

    2. Create `DrCallbackService` in `client.service`. Annotate `@Service @Transactional @RequiredArgsConstructor @Slf4j`. Dependencies: `SendRequestRecipientRepository`, `SendRequestRepository`, `CreditReservationService`.

       Public method `processDr(NexahDrPayload payload) -> NexahDrResponse`:

       Build result list. For each `NexahDrEntry` dlr in `payload.dlrList()`:

       a. Find recipient: `recipientRepository.findByGatewayMessageId(dlr.messageId())`.
          - If not found: log WARN "DR for unknown gatewayMessageId: {}", add NexahDrAck with status=0 (signal Nexah to retry — maybe we haven't persisted yet). Continue to next entry.

       b. Idempotency guard: if recipient.getSendStatus() is already `FINALIZED` or `FAIL_FINALIZED`:
          - Add NexahDrAck with status=1 (already processed — do not re-process). Continue.

       c. Parse segmentsConsumed: `Integer.parseInt(dlr.totalSmsUnit())` — wrap in try/catch; on NumberFormatException log WARN and default to 1 (conservative fallback).

       d. Set recipient fields: `recipient.setSegmentsConsumed(segmentsConsumed)`.
          Map status: if `"DELIVRD".equals(dlr.status())` -> `SendRequestStatus.COMPLETED`; else -> `SendRequestStatus.FAILED`.
          Set `recipient.setSendStatus(mapped status)`. Save recipient.

       e. Check if all recipients for the parent SendRequest are now terminal:
          - Load parent: `sendRequestRepository.findById(recipient.getSendRequestIdFk())`.
          - Load all recipients for parent: `recipientRepository.findBySendRequestIdFk(parent.getId())`.
          - Terminal states: `COMPLETED`, `FAILED`, `FINALIZED`, `FAIL_FINALIZED`.
          - If all recipients are in terminal states -> finalize parent:
            * Determine parent status: if ANY recipient is `FAILED` -> `FAIL_FINALIZED`; else -> `FINALIZED`.
            * Set `parent.setSendStatus(parentStatus)`.
            * Set `parent.setFinalizedAt(Instant.now())`.
            * Compute totalActualSegments: sum of `recipient.getSegmentsConsumed()` across ALL recipients (including those from prior DR calls). Use 0 for null segmentsConsumed (should not happen but defensive).
            * Ensure totalActualSegments > 0; if zero, set to parent.getReservedCredits() as conservative fallback (prevents debit(0) IllegalArgumentException).
            * Cap totalActualSegments to prevent over-debiting: `int debitable = Math.min(totalActualSegments, parent.getReservedCredits())`. If totalActualSegments > parent.getReservedCredits(), log WARN "SendRequest {} actual segments {} exceeds reservation {} — capping debit". Use `debitable` as the argument to debit().
            * Call `creditReservationService.debit(parent.getClientId(), parent.getReservationId(), debitable)`.
            * Save parent.
            * Log INFO "SendRequest {} finalized as {} — debited {} segments", parent.getSendRequestId(), parentStatus, debitable.

       f. Add NexahDrAck with status=1 for this entry (processed successfully). Build NexahDrAck from dlr fields (messageId, mobileNo, submitTime, sentTime, deliveryTime, responseCode, responseDescription).

       Return `new NexahDrResponse(resultList)`.

       Exception handling: wrap the per-entry logic in try/catch. On unexpected exception: log ERROR, add NexahDrAck with status=0 for that entry (Nexah will retry). Never let one bad entry abort the entire callback.
