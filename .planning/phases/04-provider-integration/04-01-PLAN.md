    1. Create `NexahProperties` as a `@ConfigurationProperties(prefix = "nexah")` record with fields: `user` (String), `password` (String), `senderid` (String), `baseUrl` (String). Annotate the config class with `@EnableConfigurationProperties(NexahProperties.class)` in `ClientConfig.java`.

    2. Create Nexah send/receive DTOs as Java records in `client.contract.nexah`:

       `NexahSendRequest`: fields `user`, `password`, `senderid`, `sms`, `mobiles` — all @JsonProperty mapped to lowercase field names as per nexahApi.md section 2.1.1.

       `NexahSmsEntry`: fields `status` (String), `smsClientId` (@JsonProperty("smsclientid")), `messageId` (@JsonProperty("messageid")), `mobileNo` (@JsonProperty("mobileno")), `errorCode` (@JsonProperty("errorcode") Integer), `errorDescription` (@JsonProperty("errordescription") String), `totalSmsUnit` (@JsonProperty("total_sms_unit") Integer — confirmed Integer in send response), `balance` (Integer).

       `NexahSendResponse`: fields `responseCode` (@JsonProperty("responsecode") int), `responseDescription` (@JsonProperty("responsedescription") String), `responseMessage` (@JsonProperty("responsemessage") String), `sms` (List<NexahSmsEntry>).

       `NexahDrEntry`: fields `responseCode` (@JsonProperty("reponsecode") String — NOTE: typo is intentional, matches Nexah spec), `responseDescription` (@JsonProperty("reponsedescription") String), `mobileNo` (@JsonProperty("mobileno") String), `messageId` (@JsonProperty("messageid") String — matches gateway_message_id), `totalSmsUnit` (@JsonProperty("total_sms_unit") String — NOTE: String not Integer in DR payload, per pitfall 2 in research), `submitTime` (@JsonProperty("submittime") String), `sentTime` (@JsonProperty("senttime") String), `deliveryTime` (@JsonProperty("deliverytime") String), `status` (@JsonProperty("status") String — "DELIVRD" or "UNDELIV"), `traffic` (@JsonProperty("traffic") String).

       `NexahDrPayload`: field `dlrList` (@JsonProperty("dlrlist") List<NexahDrEntry>).

       `NexahDrAck`: fields `responseCode` (@JsonProperty("reponsecode") int), `responseDescription` (@JsonProperty("reponsedescription") String), `messageId` (@JsonProperty("messageid") String), `mobileNo` (@JsonProperty("mobileno") String), `status` (@JsonProperty("status") int — 1=processed, 0=failed/retry), `submitTime` (@JsonProperty("submittime") String), `sentTime` (@JsonProperty("senttime") String), `deliveryTime` (@JsonProperty("deliverytime") String).

       `NexahDrResponse`: field `dlrList` (@JsonProperty("dlrlist") List<NexahDrAck>).

    3. Create `NexahClient` in `client.infrastructure.nexah`. Do NOT extend AbstractClient — AbstractClient's constructor requires a `RestRequestInterceptor` and `heartbeatPath` designed for the existing MoMo pattern (different auth model). NexahClient instead creates its own `RestTemplate` directly (same pattern but without the interceptor). Fields: `restTemplate` (RestTemplate), `properties` (NexahProperties). Inject via constructor (@RequiredArgsConstructor). Configure RestTemplate with `BufferingClientHttpRequestFactory(SimpleClientHttpRequestFactory)` and a `MappingJackson2HttpMessageConverter` with `FAIL_ON_UNKNOWN_PROPERTIES=false` — mirror the pattern in `AbstractClient.messageConverters()`.

       Method `sendSms(NexahSendRequest request) -> NexahSendResponse`: POST to `${nexah.baseUrl}/sendsms` using `restTemplate.postForObject`. Set Content-Type: application/json. Wrap with Resilience4j circuit breaker (see below). Throws `ProviderUnavailableException` if circuit is OPEN before the call, or if the call throws `RestClientException` and the circuit transitions to OPEN.

       Method `checkAvailability() -> boolean`: POST to `${nexah.baseUrl}/smscredit` with body `{user, password}`. Returns true if response is non-null and `responseCode == 1`. Used as a probe by the circuit breaker health indicator. Does NOT go through the circuit breaker itself (this is the probe, not the guarded operation).

       Circuit breaker integration: Use `@CircuitBreaker(name = "nexah", fallbackMethod = "sendSmsFallback")` on `sendSms`. The fallback method `sendSmsFallback(NexahSendRequest request, Throwable t)` throws `ProviderUnavailableException`. Import from `io.github.resilience4j.circuitbreaker.annotation.CircuitBreaker`.

    4. Add resilience4j circuit breaker config to `application.yaml`:
       ```yaml
       resilience4j:
         circuitbreaker:
           instances:
             nexah:
               slidingWindowSize: 10
               failureRateThreshold: 50
               waitDurationInOpenState: 30s
               permittedNumberOfCallsInHalfOpenState: 3
               registerHealthIndicator: true

       nexah:
         user: ${NEXAH_USER}
         password: ${NEXAH_PASSWORD}
         senderid: ${NEXAH_SENDERID}
         baseUrl: https://smsvas.com/bulk/public/index.php/api/v1
       ```
       Add these blocks after the existing `apikey:` block. Do not modify any existing yaml keys.

    1. Create `ProviderUnavailableException` in `client.contract.exception`. Extends `ApplicationException` (same base as other domain exceptions). Constructor takes `String message`. No additional fields needed. Error code: call super with `"PROVIDER_UNAVAILABLE"` or set via `getErrorCode()` if `ApplicationException` uses an ErrorCode interface — follow the same pattern as `CancelNotAllowedException` (which also carries a string error code).

    2. Create `NexahSecurityConfiguration` in `client.config`. This is a new `@Configuration @Order(0)` class that defines a `SecurityFilterChain` bean also annotated `@Order(0)`. The chain must use `.securityMatcher("/v1/provider/**")` to scope it ONLY to the provider callback path — it must NOT match `/v1/sms/**` or other client paths. Chain: disable CSRF, stateless session, `authorizeHttpRequests(auth -> auth.anyRequest().permitAll())`. No authentication filters added. This chain sits before `ClientSecurityConfiguration` (@Order(1)) so Nexah callback requests are handled without the API key filter.

       Important: Do NOT set `.securityMatcher("/v1/**")` — that would shadow the @Order(1) chain for all client paths.

    3. Create `DrCallbackResource` in `client.api`. `@RestController @RequestMapping("/v1/provider")`. Single method: `@PostMapping("/dr") public ResponseEntity<NexahDrResponse> handleDrCallback(@RequestBody NexahDrPayload payload)`. For this plan, the method body is a stub: log the payload at INFO level and return `ResponseEntity.ok(new NexahDrResponse(List.of()))`. Plan 02 replaces the stub with real processing via `DrCallbackService`. This stub allows the security configuration to be verified independently.

    4. Add `ProviderUnavailableException` handler to `ApiAdvice`. Add after the `rateLimitExceededHandler` method:
       ```java
       @ExceptionHandler(ProviderUnavailableException.class)
       @ResponseStatus(HttpStatus.SERVICE_UNAVAILABLE)
       public ErrorDto providerUnavailableHandler(final ProviderUnavailableException exception) {
           final String defaultMsg = "SMS provider is temporarily unavailable. Please retry shortly.";
           return logErrorAndReturnDTO(exception, defaultMsg, "PROVIDER_UNAVAILABLE");
       }
       ```
       Add the import for `ProviderUnavailableException` at the top of ApiAdvice.
