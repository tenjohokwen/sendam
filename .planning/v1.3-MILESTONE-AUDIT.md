## Tech Debt

No critical blockers. Three non-blocking items to address in a future phase:

### Pre-existing (not introduced by v1.3)

**1. Stale SMS credit reservation leak**
- `SmsSchedulerService.forceFinalize()` sets stale `SendRequest` to `FAIL_FINALIZED` directly without publishing `SmsFinalisedEvent`.
- `SmsFinalisedBillingListener` is never triggered → credit reservations for stale SMS are never debited or released.
- Credits held in reservation permanently for any SMS that times out via the scheduler.
- **Severity:** Medium. Silent financial inconsistency; credits effectively frozen in limbo.
- **Fix:** `forceFinalize()` should either publish `SmsFinalisedEvent(0)` (release reservation) or directly call `CreditReservationService.release()`.

**2. Boxed Long in SmsFinalisedEvent**
- `SmsFinalisedEvent.actualSegments()` returns `Long` (boxed); `FinalBookingService.book()` receives `long` (primitive).
- Auto-unboxing NPE if a future code path produces a null value.
- Currently safe because `SmsProviderReportListener` always casts a computed `int` sum.
- **Severity:** Low. Theoretical risk; guarded by current callers.
- **Fix:** Change event record field to primitive `long` or add null check at listener boundary.

### Phase 19

**3. Stale Javadoc in InsufficientPlatformBalanceException**
- Class Javadoc states "HTTP 400" but `ApiAdvice` correctly returns HTTP 422.
- No runtime impact.
- **Severity:** Trivial.
- **Fix:** Update Javadoc to read "HTTP 422 Unprocessable Entity".

### Phase 23 (Observation — Not Debt)

`ReconciliationProperties` bean is valid but not injected by `BalanceReconciliationJob`. The job reads the same YAML key via `@Scheduled` SpEL directly. Both approaches are correct and consistent. The bean is available for future consumers. No action required.
